Copilot for JetBrains gives teams more control over models and tools

A diagnostic warning can now open a Copilot fix directly in JetBrains. The new Fix action starts inline chat in agent mode when available and ask mode otherwise.

GitHub's 10 October update also adds two useful controls. Enterprise administrators can choose the default available agent model for new conversations through managed settings. An explicit choice in the model picker still takes precedence. A separate MCP setting can disable automatic server startup for Copilot and Claude.

That gives a team a starting model and a way to decide when configured tools become active. Disabling automatic startup isn't the same as removing a server or proving every future tool call safe.

Account labels, Switch Account and navigation between chat turns also get improvements. GitHub reports reliability fixes around language servers, model switching, MCP configuration and worktrees. Those are release notes, not a benchmark we've reproduced.

One compatibility change needs checking before updating: JetBrains IDE 2025.1 is no longer supported. The plugin now requires 2025.2 or later.

An agent population can change the risk even when each model stays fixed

Testing a few collaborating agents leaves a question about the size of the group. A new preprint by Erin Crawley and Hidenori Tanaka makes that question explicit.

Their ecological model links an agent population's growth to its collective cyber capability. If agents can pool useful work, success can rise with population size while the individual model stays fixed. Under the model's assumptions, a group below a critical size declines and a larger one grows. This is related to the strong Allee effect in ecology.

The threshold comes from balancing additions against losses. It depends on collaboration gains, the resources a successful attempt can add and the rate at which unauthorized agents are removed. It isn't one universal agent count.

The authors propose gradually testing larger populations in controlled environments and measuring how capability changes with group size. Communication and coordination bottlenecks can change the assumed scaling. Resource limits matter too.

This is a theoretical warning about an evaluation gap. The paper does not establish that today's systems are near a real takeoff threshold. Finding that would require empirical population data.

An agent can notice conflicting evidence and still hide it in the answer

The agent sees two sources disagree. Then its final answer sounds completely settled. That's the behaviour this study tries to measure.

The researchers define three observable actions: identify a knowledge gap, try to solve it with fresh tool use and tell the user when uncertainty remains. They call these Identify, Solve and Escalate. Task accuracy is scored separately.

They test controlled conflicts and conflicts that arise during multi-step tasks, using four agent frameworks with several model configurations. Some configurations recognize conflict early but don't keep it visible or communicate it in an incorrect final answer. Higher accuracy doesn't automatically mean better uncertainty handling.

An important detail: the Solve score measures a bounded attempt to resolve the gap. It doesn't itself prove the answer became correct. The paper also distinguishes matched controlled comparisons from naturally occurring cases where task composition can differ.

A prompting intervention often improves uncertainty reporting while reducing accuracy. The result depends on the backbone, harness and evaluation environment together.

The public repository includes trajectories and per-turn judgments for inspecting those behaviours. These are the authors' reported experiments, not a reproduction by Inside AI.

PASS allocates fine-tuning examples to concepts with weaker support

A fixed fine-tuning budget has to cover concepts the pretrained model knows unevenly. Giving every concept the same share can leave the weak ones short.

PASS is an instruction selection method built around that problem. The paper defines a prior barrier: how strongly competing concepts are supported relative to the desired concept. It estimates useful distinguishing evidence in candidate instructions and allocates more of the selection budget where coverage remains insufficient. Redundant or harmful evidence is penalized.

The experiments use Mistral-7B and Qwen2.5-7B with 5,000 or 10,000 selected records from a pool of 300,932. All selectors share the fine-tuning settings within each comparison.

In the reported aggregate table, Mistral-7B with 5,000 PASS-selected records scores 51.5. The strongest competing selector with 10,000 records scores 50.9. The gains aren't uniform: on Qwen2.5-7B at 10,000 records, PASS and random selection both round to 65.6.

Those are averages across five capability benchmark scores. They aren't a guarantee that a smaller dataset will win on your task. The method's reference-derived concepts and pretrained support estimates are part of the setup you'd need to examine.

AAArena tests agents that improve game programs from replays

Here the AI's job is to build the player. It reads game rules, runs matches, studies replays and revises executable game policies. The model weights stay fixed.

AAArena turns that development loop into a benchmark with 12 adversarial games and 1,920 archived human programs. Agents have separate budgets for selected matches and full opponent-pool evaluations. Their retained best officially evaluated policy determines the reported result.

The authors evaluate seven model and harness configurations. Opus5.5 with Claude Code finishes first in six frozen human-program ladders. No evaluated configuration tops the other six. Larger rule descriptions generally accompany weaker results.

Replay feedback and opponent selection help in the reported experiments. The study also examines learning from other players' replays. Those replay labels describe where the experience came from, rather than naming a reinforcement-learning algorithm.

A revision can make the current policy worse while the retained-best score stays unchanged. Looking only at that final score would miss the development path. The comparison also includes different harnesses, so it doesn't isolate model effects.

Code and game resources are linked below. This is a competition-style evaluation against archived programs, not a claim that the model mastered every game or improved its own weights.
