How a VQ VAE turns an image into a code from a learned dictionary

Choosing an image code is one problem. Learning which codes to sample is another.

Author: Somil Singh · Inside AI

Deep Learning Models · Part 03

A decoder can learn to reconstruct an image from a dictionary entry. That still leaves a question: which entry should we choose to make another image?

If the model learned the dictionary, why does generation need another rule?

A VQ VAE gives the encoder a learned dictionary of codes. The encoder chooses an entry and the decoder uses its vector to reconstruct the image. A separate prior tells us which entries to sample when there is no input image.

These are my visual notes for Part 03 of Inside AI: Deep Learning Models. We will connect that distinction to a small PyTorch experiment and its recorded output. The original VQ VAE paper introduces the approach and training objective.

Figure 1. Original teaching schematic.

1. What changes from a Gaussian VAE

In a common Gaussian VAE, the encoder predicts a distribution and training samples a continuous code. Here it produces a continuous vector zₑ(x), then chooses the closest entry from a learned codebook E = {e₀, …, eK₋₁}.

k(x) = argminj ‖zₑ(x) − ej‖²
zq(x) = ek(x)

The index k is discrete. The selected code eₖ is a learned continuous vector. These are related but different objects. The decoder consumes the vector, while a prior can assign probabilities to the indices.

For a larger image model, the encoder often outputs a grid of vectors and quantizes each location. Our experiment deliberately uses one code for the entire image. That keeps the codebook and generation process visible without a large network or dataset.

2. The decoder still needs a training signal

The decoder takes zq and predicts pixel logits. For our binary patterns, sigmoid converts each logit into a Bernoulli probability. Binary cross entropy measures how well those predictions explain the observed pixels. During training we use BCEWithLogits through PyTorch’s functional equivalent, which combines the sigmoid and loss stably.

There is a problem upstream: nearest code selection uses argmin. Ordinary differentiation does not give us a useful derivative of the selected index with respect to the encoder vector. If we simply backpropagate through that selection, the encoder would not receive the reconstruction gradient it needs.

We use a straight through construction:

z_st = ze + (zq - ze).detach()

The forward value is zq. Autograd treats the derivative with respect to ze as the identity. This is a deliberately chosen gradient surrogate. It is not the exact derivative of nearest neighbor selection. Part 04 will trace each gradient with actual tensors.

3. Three losses with separate jobs

For the gradient based codebook update used here, minimize:

L = reconstruction
  + ‖stopgrad(zₑ) − zq‖²
  + β ‖zₑ − stopgrad(zq)‖²

Reconstruction trains the decoder and, through our straight through path, the encoder. The codebook term moves selected dictionary entries toward encoder outputs. The commitment term encourages the encoder to stay near the entries it uses. The stop gradients keep those last two jobs separate.

We use β = 0.25 for this demonstration. Our reconstruction cost sums pixels and averages images. Both squared vector costs sum coordinates and average images. Those reductions are part of the configuration. A β that worked elsewhere is not automatically appropriate for every scaling convention.

Exponential moving averages are another way to update the codebook. That is an alternative to the gradient update implemented here, not an extra update to apply accidentally on top of it.

Figure 2. Stop gradients separate codebook learning from encoder commitment.

4. A codebook is not a generation prior

Training the reconstruction model teaches the decoder what each code means. It does not yet tell us which indices should occur or how a grid of indices should fit together.

After learning the representation, a prior models the encoded training data. For grids, the original work uses autoregressive priors that model dependencies between positions. Sampling all grid entries independently would ignore those dependencies.

Our entire image has one index, so a categorical prior is sufficient. We encode the eight training patterns, count each selected index and divide by the total. This is maximum likelihood estimation for a categorical distribution.

prior probability of code j = count(j) / number of training images
generation: sample k from that prior, then decode ek

There is no input image during generation. Uniformly sampling a dictionary is appropriate only if a uniform distribution actually represents the intended code usage. Unused entries should not quietly receive sample probability in this fitted prior.

5. The tiny experiment and its deliberate warm start

The dataset contains four vertical bars and four horizontal bars, each a binary 4 by 4 image. The encoder maps 16 pixels to an eight dimensional vector. The codebook has eight entries. The decoder maps one selected vector back to 16 pixel logits.

We first train an ordinary autoencoder for 200 steps and initialize each codebook entry from one encoded template. We then train the quantized model for 401 steps. This warm start makes the eight code identities easy to inspect. It is a teaching choice that differs from the original paper’s setup and it benefits directly from knowing all eight templates.

This experiment therefore demonstrates quantization, gradient routing and sampling. It does not demonstrate discovery of a rich representation from an unseen image collection. A one code model can only produce one of its code conditioned decoder distributions. It cannot create arbitrary new arrangements of bars.

6. A tiny VQ VAE you can actually run

Install PyTorch and Matplotlib with pip install torch matplotlib. Save the three blocks below in order as one Python file and run it. Together they print the code assignments, fitted prior and sampled IDs and save the figure below.

Step 1. Build the encoder, decoder and dictionary. The warm start is a deliberate teaching choice using all eight templates.

"""A one-code VQ VAE with a learned categorical prior on eight tiny images."""
from pathlib import Path
import platform
import torch
from torch import nn
from torch.nn import functional as F
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

torch.manual_seed(7)
torch.set_num_threads(1)
out = Path(__file__).resolve().parent / "images"
out.mkdir(exist_ok=True)
print(f"Python {platform.python_version()} | PyTorch {torch.__version__} | CPU | seed 7")
vertical = torch.eye(4).repeat(1, 4).view(4, 4, 4)
data = torch.cat([vertical, vertical.transpose(1, 2)]).reshape(8, 16)
encoder = nn.Sequential(nn.Linear(16, 32), nn.ReLU(), nn.Linear(32, 8))
decoder = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 16))
embedding = nn.Embedding(8, 8)

# Warm start is a deliberate teaching choice, not the paper's initialization.
optimizer = torch.optim.Adam(list(encoder.parameters()) + list(decoder.parameters()), lr=0.01)
for _ in range(200):
    loss = F.binary_cross_entropy_with_logits(decoder(encoder(data)), data)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
with torch.no_grad():
    embedding.weight.copy_(encoder(data))

Step 2. Quantize and train with three costs. The straight through path carries the reconstruction gradient to the encoder.

def quantize(x):
    ze = encoder(x)
    distances = (ze[:, None, :] - embedding.weight[None, :, :]).square().sum(-1)
    ids = distances.argmin(1)
    zq = embedding(ids)
    return ze, zq, ids

optimizer = torch.optim.Adam(
    list(encoder.parameters()) + list(decoder.parameters()) + list(embedding.parameters()), lr=0.002)
for step in range(401):
    x = data[torch.randint(8, (64,))]
    ze, zq, ids = quantize(x)
    z_st = ze + (zq - ze).detach()
    reconstruction = F.binary_cross_entropy_with_logits(decoder(z_st), x, reduction="none").sum(1).mean()
    codebook = (zq - ze.detach()).square().sum(1).mean()
    commitment = (ze - zq.detach()).square().sum(1).mean()
    loss = reconstruction + codebook + 0.25 * commitment
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    if step in (0, 400):
        print(f"Step {step:3d} | reconstruction {reconstruction.item():.4f} | codebook {codebook.item():.4f} | commitment {commitment.item():.4f}")

Step 3. Fit the prior and generate without the encoder. Sample code IDs, look up their vectors and plot the decoder means.

# Fit the maximum likelihood categorical prior after freezing the representation.
with torch.no_grad():
    _, zq, ids = quantize(data)
    counts = torch.bincount(ids, minlength=8).float()
    prior = counts / counts.sum()
    new_ids = torch.multinomial(prior, 8, replacement=True)
    reconstructions = decoder(zq).sigmoid().view(8, 4, 4)
    generated = decoder(embedding(new_ids)).sigmoid().view(8, 4, 4)
    bce = F.binary_cross_entropy(reconstructions.flatten(1), data, reduction="none").sum(1).mean()
    perplexity = (-(prior[prior > 0] * prior[prior > 0].log()).sum()).exp()
print("Encoded IDs:", ids.tolist())
print("Prior probabilities:", [round(v, 3) for v in prior.tolist()])
print("Sampled IDs:", new_ids.tolist())
print(f"Used codes: {(counts > 0).sum().item()}/8 | perplexity: {perplexity.item():.3f} | reconstruction BCE/image: {bce.item():.4f}")
assert (counts > 0).sum().item() == 8
assert torch.isfinite(generated).all()
torch.save({"ids": ids, "prior": prior, "generated": generated}, out.parent / "result.pt")
fig, axes = plt.subplots(3, 8, figsize=(12, 5))
for row, images in enumerate((data.view(8, 4, 4), reconstructions, generated)):
    for col in range(8):
        axes[row, col].imshow(images[col].numpy(), cmap="gray", vmin=0, vmax=1)
        axes[row, col].axis("off")
        axes[row, col].set_title(["Input", "Reconstruction", "Prior sample"][row], fontsize=9)
fig.suptitle("Actual tiny VQ VAE output: decoder means", fontsize=15)
fig.tight_layout()
fig.savefig(out / "actual-output.png", dpi=180)
plt.close(fig)

Figure 3. Recorded experiment plot from 2 October 2026. The bottom row shows decoder means.

The bottom row displays decoder means after sampling code IDs. We do not take an additional Bernoulli pixel draw. Calling these decoder means makes that choice explicit: sampling the code and sampling the observation are separate operations.

The printed 0.0000 is rounded to four decimals, not a claim of exact zero error. The reconstruction BCE reports the final model on all eight templates. Training lines report the minibatch loss before the update at that step. They answer slightly different questions.

7. What the code usage tells us

We report how many entries are used and exp(entropy) of the empirical code distribution. This perplexity is an effective number of used codes. It equals eight when the eight entries are used equally. It is not text model perplexity or an image quality score.

A model can use many codes while reconstructing badly. It can also reconstruct a small dataset well while leaving many entries unused. Inspect reconstruction, code frequencies and generated outputs together. In larger experiments, repeated use of only a few entries can reduce the useful discrete capacity.

Practical warning signs include dead entries, encoder outputs that drift far from their selected codes and a prior that produces implausible combinations. The corresponding checks are code counts, quantization error and actual prior samples. No single loss replaces those checks.

8. Training and generation take different routes

Training takes an image, encodes it, chooses a code and compares decoder predictions with the image. Prior fitting takes the resulting indices. Generation starts with sampled indices and runs the decoder alone.

That is the mechanism you should be able to sketch in an interview. If someone asks where the Gaussian KL went, you now have the right question for the companion article.

Try changing the prior frequencies after training. More probability on one code should produce more of its template, even though the decoder weights stay fixed. Then ask what changes when the latent becomes a grid and neighboring indices matter.

Keep these five ideas

  1. The code ID is discrete. The selected dictionary vector is continuous.
  2. The decoder reconstructs from that selected vector.
  3. The straight through path is a gradient surrogate for training the encoder.
  4. The codebook and commitment terms update different parameters.
  5. A generation prior chooses the IDs. A codebook alone does not provide their distribution.
