The VQ VAE gradient trick: what learns when a code is selected?

How can an encoder learn when its nearest code choice has no useful ordinary gradient?

Somil Singh · Inside AI

Deep Learning Models · Part 04

An encoder can choose a dictionary entry with one short line. Learning from that choice is the interesting part.

If the selected entry stays the same while the encoder moves a little, what tells the encoder where to move next?

The missing mechanism is a deliberately chosen backward path. In these visual notes we will calculate one code choice, trace the three learning signals and check the numbers with real tensors. Part 03 explains the complete VQ VAE and its tiny generation example; this companion makes its gradient paths visible. ❤️

Figure 1. Teaching schematic: nearest selection determines the forward value; a chosen surrogate carries the reconstruction gradient back. This is not measured model output.

1. An index chooses a vector

Imagine a paint chart with a small set of colours. You can describe a colour precisely but the chart gives you only a few available choices. Picking the nearest swatch replaces your description with one available entry.

Vector quantization does that with numerical vectors. The encoder produces zₑ(x). A learned dictionary E contains K vectors eⱼ, each with D coordinates. The nearest entry supplies the decoder input zq. Its integer index k and its continuous vector eₖ are different objects.

k(x) = argminⱼ ||zₑ(x) − eⱼ||²
zq(x) = eₖ(x)

An image model can make this choice at each position of a latent grid. Our check uses a single vector so that every number and gradient can be inspected. It does not test image quality or spatial dependencies.

2. Nearest selection has regions and boundaries

Take zₑ = (0.3, 0.4) and dictionary entries e₀ = (0, 0), e₁ = (1, 1) and e₂ = (−1, 1). Their squared distances are 0.25, 0.85 and 2.05. Entry zero wins and the decoder receives (0, 0).

Figure 2. Calculated assignment example. Distances are computed from the displayed vectors, not learned from an image dataset.

Within a region around an entry, small changes to the encoder vector leave the selected vector unchanged. At a boundary the selection can jump. The true local derivative is zero inside a region and is not ordinarily defined at the jump. It cannot supply the encoder with the useful reconstruction signal we want.

The decoder learns how to use its vector input. The encoder needs feedback about how that input should change. The codebook needs its own rule for moving the selected entry. A single nearest choice does not settle all three jobs.

3. Three costs keep the learning jobs separate

For gradient based codebook updates, the representation objective is:

L = Lrec + ||stopgrad(zₑ) − zq||²
         + β ||zₑ − stopgrad(zq)||²

Figure 3. Objective schematic for gradient based codebook updates. Colours identify the jobs; text also names their destinations.

Reconstruction asks whether the decoder explains the input. It trains the decoder and reaches the encoder through the surrogate introduced next. It does not train the selected embedding through that surrogate expression.

Codebook alignment pulls the selected entry toward the encoder output. Stop gradient treats the encoder output as a fixed target for this cost. In our example its gradient at entry zero is 2(zq − zₑ) = (−0.6, −0.8). Gradient descent subtracts that vector and moves the entry toward (0.3, 0.4).

Commitment pulls the encoder output toward its selected entry. At β = 0.25 its encoder gradient is 2β(zₑ − zq) = (0.15, 0.2). The dictionary is a fixed target in this branch. This limits drift but cannot guarantee useful representations or prevent every unused code.

Our squared costs sum coordinates. A full model must also specify its reconstruction and batch reductions. Changing a sum into a mean changes the relative scale of these costs. Exponential moving averages are an alternative codebook update method; do not accidentally add them to the gradient update without defining a deliberate algorithm. The original VQ VAE paper gives the core objective and the alternative update.

4. One value can have a different backward path

Stop gradient keeps a value while removing that branch from autograd. In PyTorch the detached tensor shares storage, so detach does not make in-place changes harmless.

z_st = ze + (zq - ze).detach()

The forward arithmetic gives zq: zₑ + zq − zₑ = zq. In the backward graph only the first zₑ contributes a derivative. Under this surrogate, ∂z_st/∂zₑ = I and this expression gives no reconstruction gradient to zq.

Figure 4. Surrogate gradient schematic. The stopped correction keeps its forward value. The identity backward path is chosen, not the true derivative of nearest selection.

Let our decoder stand-in be Lrec = ||z_st − (1, 0)||². With z_st = (0, 0), the input gradient is (−2, 0). It reaches zₑ through the surrogate. A real decoder also learns its parameters and supplies its own input derivative instead of this simple quadratic derivative.

An easy mistake is to say the line makes argmin differentiable. It supplies a useful derivative for learning. The straight through estimator paper discusses this family of surrogate estimators. Removing a detach changes which parameters a cost trains even when the forward value looks unchanged.

5. Representation learning and generation use different routes

During training an image goes through the encoder, nearest selection and decoder. The reconstruction target is the image. Once that representation is learned, a prior models the resulting indices.

Figure 5. Two route schematic. Generation needs no input image or encoder. A grid prior must model relevant dependencies between positions.

If q(k|x) puts probability one on the chosen index k* and p(k) is uniform over K entries, then KL(q||p) = −log p(k*) = log K. It is constant for fixed K. M independent uniform positions contribute M log K. This explains why the representation objective above has no changing Gaussian KL cost.

A nonuniform prior changes the value. With probability 0.8 on the selected entry the same point posterior gives −log(0.8), about 0.223144 nats instead of log(3), about 1.098612 nats.

For one index, categorical counts can fit its frequency distribution. For a grid, a prior can factor as p(k₁,…,kM) = ∏ₘ p(kₘ|k₁,…,kₘ₋₁). Independent sampling ignores those dependencies. A dictionary says what each code means; a prior says which codes and combinations should occur.

6. Usage and gradient checks reveal different failures

Many entries stay unused. Inspect assignment counts and quantization error alongside reconstruction. An unselected entry receives no selected codebook gradient in the method here. Initialization, moving encoder outputs and data all affect usage. Part 03 deliberately used a warm start; its eight used codes do not prove dead codes cannot occur.

The encoder moves too far from its selected entries. Check the commitment gradient and its scale relative to reconstruction. A total loss alone can conceal the mismatch. Reductions, dimension and β affect the balance.

Reconstructions work but prior samples do not. Check the learned index frequencies and actual decoder outputs from prior samples. Grid dependencies and decoder quality matter. High code entropy is not a semantic quality score.

Track effective code count exp(−∑ⱼ pⱼ log pⱼ) with the usage histogram. It equals K for equal usage of K codes and approaches one for a single dominant code. It measures usage diversity, not text model perplexity or image realism. These checks are clues rather than complete diagnoses.

Keep these three ideas

  1. The index selects a continuous dictionary vector. Nearest selection determines the forward value.
  2. The surrogate carries reconstruction feedback to the encoder; codebook alignment and commitment have separate gradient destinations.
  3. The prior models index frequencies and dependencies. A learned dictionary alone is not a generation distribution.

7. Run a small gradient audit

Install PyTorch and Matplotlib with pip install torch matplotlib. Save these three blocks in order as example.py and run python example.py. No downloaded dataset or GPU is needed. This is a gradient check, not another VQ VAE training benchmark.

Step 1. Set up the three vectors. We fix seed 7 and prepare an output folder. The computation is deterministic; the seed is recorded for reproducibility.

"""Trace the three VQ VAE gradient paths with exact small tensors."""
from pathlib import Path
import math
import platform
import torch
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

torch.manual_seed(7)
torch.set_num_threads(1)
out = Path(__file__).resolve().parent / "images"
out.mkdir(exist_ok=True)
print(f"Python {platform.python_version()} | PyTorch {torch.__version__} | CPU | seed 7")
base_ze = torch.tensor([[0.3, 0.4]])
base_codes = torch.tensor([[0.0, 0.0], [1.0, 1.0], [-1.0, 1.0]])

Step 2. Give each objective a fresh graph. We inspect the encoder and dictionary gradients separately. Fresh tensors avoid adding gradients from earlier backward calls. The assertions check that the intended branches are active or absent.

gradients = []
for objective in ("reconstruction", "codebook", "commitment"):
    ze = base_ze.clone().requires_grad_()
    codes = base_codes.clone().requires_grad_()
    ids = ((ze[:, None] - codes[None]).square().sum(-1)).argmin(1)
    zq = codes[ids]
    z_st = ze + (zq - ze).detach()
    losses = {
        "reconstruction": (z_st - torch.tensor([[1.0, 0.0]])).square().sum(),
        "codebook": (zq - ze.detach()).square().sum(),
        "commitment": 0.25 * (ze - zq.detach()).square().sum(),
    }
    losses[objective].backward()
    encoder_grad = torch.zeros_like(ze) if ze.grad is None else ze.grad
    code_grad = torch.zeros_like(codes) if codes.grad is None else codes.grad
    gradients.append([encoder_grad.norm().item(), code_grad.norm().item()])
    print(f"{objective}: encoder gradient {encoder_grad.tolist()} | code 0 gradient {code_grad[0].tolist()}")
    if objective == "reconstruction":
        assert ze.grad is not None and codes.grad is None
    if objective == "codebook":
        assert ze.grad is None and codes.grad is not None
    if objective == "commitment":
        assert ze.grad is not None and codes.grad is None

Step 3. Print the prior check and plot the measured norms. Zero in the display represents an absent gradient path in this experiment. It does not mean an optimizer silently updated that branch.

print("Chosen code: 0 | forward z_st: [[0.0, 0.0]]")
print(f"Point posterior KL to uniform prior with K=3: {math.log(3):.6f} nats")
print(f"Same chosen code with prior probability 0.8: {-math.log(0.8):.6f} nats")
fig, ax = plt.subplots(figsize=(8, 4.5))
xs = torch.arange(3).numpy()
ax.bar(xs - 0.18, [g[0] for g in gradients], width=0.36, color="#168a87", label="Encoder gradient norm")
ax.bar(xs + 0.18, [g[1] for g in gradients], width=0.36, color="#d77d42", label="Codebook gradient norm")
ax.set_xticks(xs, ["Reconstruction", "Codebook", "Commitment × 0.25"])
ax.set(ylabel="Gradient norm", title="Actual gradient routing in this numerical example")
ax.legend(frameon=False)
fig.tight_layout()
fig.savefig(out / "actual-gradients.png", dpi=180)
plt.close(fig)

These bars test routing for one two-coordinate example. Their relative heights are not universal: decoder derivatives, reductions, dimension, data and β change the magnitudes. They do not measure image quality or prove a model will train successfully.

The line to remember is ze + (zq - ze).detach(): selected vector forward, encoder path backward.
