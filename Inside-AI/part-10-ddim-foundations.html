Why DDIM can change the sampling path without changing the noise task

mediumsubstackxcompany

How can the same noise predictor follow a different path back to data?

Somil Singh · Inside AI

Deep Learning Models · Part 10

Part 09 kept the predictor fixed and tried shorter DDIM schedules. Four clusters still appeared at 20 steps. Their spread changed though.

Lemme unpack the update behind that result. We can check its variance budget, recover the adjacent DDPM mean and measure what happens when the predicted noise is slightly wrong. No new training run needed for this one.

Schematic: the training pair stays at one noise level while the sampler chooses how to move between levels.

1. A noisy level is a distribution, not a whole trajectory

Start with the familiar corruption equation:

x_t = sqrt(A_t) x_0 + sqrt(1 - A_t) epsilon.

Here A_t is the cumulative product of the per-step signal factors. A_0 = 1. Later noisy times have smaller A_t. Epsilon is standard Gaussian noise. These are the DDPM forward marginals. DDPM paper, equations 4 and 14.

Condition on a particular clean value x_0. Then the mean is sqrt(A_t) x_0 and the variance is 1 - A_t. That's all a single-time marginal tells us. It doesn't specify how noise at two times is correlated.

Our scalar check takes x_0 = 1.2 and A_t = 0.25. Its noisy mean is 0.6 and its variance is 0.75. There are many ways to connect that distribution to an earlier level with A_s = 0.64.

2. The variance has a budget

DDIM constructs alternative joint paths while retaining those single-time marginals. Its reverse update replaces the unknown clean value with a prediction. DDIM paper, equations 7, 9 and 12.

Use t for the current noisy time and s for an earlier time. Write a = A_t and b = A_s, so 0 < a < b <= 1.

The predicted clean value is:

x0_hat = (x_t - sqrt(1 - a) epsilon_hat) / sqrt(a).

Then move to s:

x_s = sqrt(b) x0_hat + sqrt(1 - b - sigma²) epsilon_hat + sigma z.

The signal term gets sqrt(b). The old residual gets a direction coefficient. Fresh independent Gaussian noise z gets sigma.

For this diagnostic only, suppose we know x_0 and the actual epsilon that corrupted it. The clean estimate is exact. The two noise terms have total variance (1 - b - sigma²) + sigma² = 1 - b. Same budget for every admissible sigma. Their dependence on the old state changes.

Knowing the corruption noise is stronger than having an optimal predictor. At generation time the network sees x_t and t. It doesn't see the hidden x_0 or the individual noise draw.

Schematic: three eta choices share a target conditional mean of 0.96 and variance of 0.36. The experiment below checks sampled values.

3. The objective still asks for predicted noise

The usual simplified loss samples one clean example, one time and one corruption noise:

L = E[w_t ||epsilon - f_theta(x_t, t)||²].

For an unrestricted function, its best prediction is the conditional mean E[epsilon | x_t, t]. Expand the square around that mean: the expected error becomes the unavoidable conditional variance plus the squared distance from the mean. The cross term vanishes. A positive weight at that time doesn't change this pointwise minimizer.

A finite network shares parameters across times. It can trade accuracy at one level for accuracy at another. Different loss weights can therefore change its fitted solution. The DDIM paper's weighted-objective argument includes a separate-parameters condition; don't turn it into a promise that every finite shared network has identical optima.

The shared marginal noise task makes a fitted DDPM predictor usable in the DDIM sampler. It doesn't certify perfect samples on every schedule.

Schematic: the target noise is available during corruption. The clean value is hidden from the predictor.

4. Eta chooses the fresh noise and changes the coefficients

Use the generalized variance from the authors' implementation:

sigma² = eta² (1 - b)/(1 - a) (1 - a/b).

Eta = 0 removes fresh step noise. Eta = 1 with adjacent original times recovers the DDPM posterior variance. Authors' sampler code.

Let's put numbers into the update. Take x_t = 0.9 and epsilon_hat = 0.6 with a = 0.25 and b = 0.64. The clean estimate is about 0.760770. At eta = 0 the direction coefficient is 0.6. At eta = 1 some of that noise budget moves into sigma z. The output block gives both values with z fixed to zero.

Now perturb only epsilon_hat by delta while holding x_t, the times, eta and z fixed. Substitution gives:

Delta x_s = [sqrt(1 - b - sigma²) - sqrt(b/a) sqrt(1 - a)] delta.

The coefficient measures local sensitivity to a prediction error. Our central finite difference checks it against the implemented update. Later steps will see a changed state and make changed predictions too, so this one coefficient isn't a full trajectory error bound.

Schematic: the numeric inputs are fixed. The runnable check reports the resulting output and derivative.

5. Deterministic steps still start from random noise

At eta = 0 a fixed predictor, fixed schedule and fixed initial state produce a fixed output. The initial noise is still random. That's where the generated distribution comes from.

Training chooses noisy levels from the original schedule. Generation can choose a subset of those levels and compute the correct a and b for each jump. Skipping a level doesn't mean applying an adjacent-step coefficient ten times further away.

The last jump uses b = A_0 = 1. Both residual coefficients vanish and the update returns the predicted clean value. Don't evaluate the predictor at the clean endpoint; evaluate it at the current noisy time then perform that final jump.

Schematic: this lesson checks the algebra with an analytic toy predictor. It doesn't train an image model.

6. What these checks can and can't catch

A negative square-root argument often points to reversed time ordering, the wrong cumulative coefficient or an invalid variance. Check those before clipping. The code allows tiny roundoff error only after asserting the variance budget.

The known-noise marginal check verifies a conditional construction. Generation uses a predicted conditional mean instead. Those are different tests.

An adjacent eta = 1 identity checks the algebra against a DDPM posterior mean with zero fresh noise. It doesn't prove a skipped eta = 1 schedule reproduces all original DDPM samples.

Finally, the four-Gaussian experiment reuses the analytic predictor from Part 09. It isolates finite schedule behaviour. Cluster counts and distance to centres are diagnostics here. Lower distance alone can mean the clusters have become too narrow (the target within-cluster mean squared radius is about 0.0288).

Keep these three ideas

  1. A single-time noise distribution leaves room for different correlations between times.
  2. The DDIM update splits a fixed variance budget between the reused residual and fresh noise.
  3. A deterministic schedule can be repeatable and still change the output when its time grid changes.

7. Run the three checks

Use Python with NumPy and Matplotlib. Install those packages if needed with python -m pip install numpy matplotlib. Run the three blocks in order in one script or notebook. The last block writes the measured plot to the current directory.

Step 1. Check conditional marginals. Here we supply the actual corruption noise and known clean value. Eta changes their coupling while the target mean and variance stay fixed.

import numpy as np
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import platform
rng = np.random.default_rng(31)
def coefficients(a, b, eta):
    assert 0 < a < b <= 1 and 0 <= eta <= 1
    variance = eta**2 * (1-b)/(1-a) * (1-a/b)
    direction2 = 1-b-variance
    assert direction2 >= -1e-12
    return np.sqrt(max(variance, 0)), np.sqrt(max(direction2, 0))
def update(x, eps, a, b, eta=0, z=0):
    sigma, direction = coefficients(a, b, eta)
    clean = (x-np.sqrt(1-a)*eps)/np.sqrt(a)
    return np.sqrt(b)*clean + direction*eps + sigma*z
a, b, x0 = 0.25, 0.64, 1.2
n = 100000
eps, z = rng.normal(size=n), rng.normal(size=n)
xt = np.sqrt(a)*x0 + np.sqrt(1-a)*eps
print(f"Python {platform.python_version()} | NumPy {np.__version__} | CPU | seed 31")
print(f"known x0={x0} | conditional draws={n} | no training")
marginals = []
for eta in (0, 0.5, 1):
    xs = update(xt, eps, a, b, eta, z)
    sigma, direction = coefficients(a, b, eta)
    exact_var = direction**2 + sigma**2
    assert abs(exact_var-(1-b)) < 1e-12
    marginals.append((eta, xs))
    print(f"eta={eta:.1f} | mean={xs.mean():.6f} | variance={xs.var():.6f}")
print(f"target mean={np.sqrt(b)*x0:.6f} | variance={1-b:.6f}")

Step 2. Check one-step sensitivity and the adjacent DDPM identity. The finite difference holds the input state fixed. The DDPM comparison uses zero fresh noise so the means can be compared directly.

# Hold x, time, eta and z fixed. Perturb only the predicted noise.
x, e, h = 0.9, 0.6, 1e-6
clean = (x-np.sqrt(1-a)*e)/np.sqrt(a)
for eta in (0, 1):
    sigma, direction = coefficients(a, b, eta)
    gain = direction-np.sqrt(b/a)*np.sqrt(1-a)
    fd = (update(x, e+h, a, b, eta)-update(x, e-h, a, b, eta))/(2*h)
    assert abs(fd-gain) < 1e-8
    print(f"eta={eta} | clean={clean:.6f} | next={update(x,e,a,b,eta):.6f} | gain={gain:.6f}")
T = 200
beta = np.linspace(0.0001, 0.05, T)
A = np.r_[1., np.cumprod(1-beta)]
t, s = 100, 99
alpha = A[t]/A[s]
ddpm_mean = (xt-(1-alpha)*eps/np.sqrt(1-A[t]))/np.sqrt(alpha)
error = np.max(np.abs(update(xt,eps,A[t],A[s],eta=1)-ddpm_mean))
assert error < 1e-12
print(f"adjacent eta=1 DDPM mean max error={error:.2e}")

Step 3. Compare finite deterministic schedules. This predictor is the exact conditional mean for the specified mixture. It isn't an oracle for each example's hidden noise. All schedules start from the same 4096 vectors.

# The exact conditional-mean predictor for a four-Gaussian toy.
centres = np.array([[-1.,-1.],[-1.,1.],[1.,-1.],[1.,1.]])
v0 = 0.12**2
initial = rng.normal(size=(4096,2))
def predictor(x, t):
    a = A[t]
    v = a*v0 + 1-a
    delta = x[:,None,:]-np.sqrt(a)*centres[None,:,:]
    logits = -(delta**2).sum(axis=2)/(2*v)
    w = np.exp(logits-logits.max(axis=1,keepdims=True))
    w /= w.sum(axis=1,keepdims=True)
    return np.sqrt(1-a)*(x-np.sqrt(a)*(w@centres))/v
def sample(calls):
    times = np.rint(np.linspace(T,1,calls)).astype(int)
    assert len(np.unique(times)) == calls
    x = initial.copy()
    for t,s in zip(times,np.r_[times[1:],0]):
        x = update(x,predictor(x,int(t)),A[t],A[s])
    return x
results = {k:sample(k) for k in (200,20,5)}
assert np.array_equal(sample(20),sample(20))
print("same initial noise + same eta=0 schedule: identical=True")
print(f"terminal A={A[-1]:.6f} | samples={len(initial)}")
for calls,x in results.items():
    d2 = ((x[:,None,:]-centres[None,:,:])**2).sum(axis=2)
    counts = np.bincount(d2.argmin(axis=1),minlength=4)
    print(f"calls={calls:3} | centre MSE={d2.min(axis=1).mean():.6f} | counts={counts.tolist()}")
print(f"200 vs 20 paired max difference={np.abs(results[200]-results[20]).max():.6f}")
fig, axes = plt.subplots(1,3,figsize=(12,3.9),sharex=True,sharey=True)
for ax,(calls,x) in zip(axes,results.items()):
    ax.scatter(x[:,0],x[:,1],s=2,alpha=.35,c="#087F8C")
    ax.scatter(centres[:,0],centres[:,1],marker="x",c="#C66B2B",s=60)
    ax.set(title=f"{calls} evaluations",xlabel="x coordinate",xlim=(-2.4,2.4),ylim=(-2.4,2.4))
    ax.set_aspect("equal")
axes[0].set_ylabel("y coordinate")
fig.suptitle("Inside AI · Deep Learning Models · Part 10\nSame initial noise, same predictor, different finite schedules")
fig.tight_layout()
fig.savefig("ddim-foundations-output.png",dpi=180)
print("Saved ddim-foundations-output.png | measured toy, no image benchmark")

The fixed 20-step run repeats exactly here. Its output differs from the 200-step run. The conditional marginal checks stay close to their target moments and the two algebraic checks pass their tolerances. These results cover this implementation and toy distribution. They aren't image-quality scores, a speed benchmark or proof of exact finite-step sampling. The terminal mixture is only approximately standard Gaussian because A_T is small but nonzero.
